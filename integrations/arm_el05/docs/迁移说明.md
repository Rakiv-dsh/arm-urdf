# 机械臂 EL05 接入 hand-host（迁移说明）

这个目录是一个标准的 **hand-host 手型包**（`dexhand.hand.v1`），把"机械臂"当成一个 5 关节的"手"接进去。
放进上位机就能用，同时和本仓库的 ROS 侧保持同一套协议与数据源。

## 一、装

把整个目录复制到上位机仓库：

```
hand-host/app/resources/hands/arm_el05/
  manifest.json
  driver_adapter/driver.py
  calibration.json
  model/arm.urdf
  gestures/
```

打开上位机 →「手型管理」应该能看到 **机械臂 EL05（5 轴 · SocketCAN）**；
「连接管理」里端点填 `can0`、协议选 `socketcan`、速率 1000000。

> 端点就是 Linux/WSL 里的 SocketCAN 接口名。Windows 上要先通过 usbipd 把 CANHUB 过继进 WSL。

## 二、字段对照（ROS 侧 ↔ 上位机包）

| 概念 | ROS 侧（本仓库） | 上位机包 |
|---|---|---|
| 关节名 | `joint_limits.yaml` 的 `name` | `manifest.json` → `fingers[].joints[].name` |
| 电机号 | `motor.can_id`（21~25） | `motor_id` |
| 限位 | `lower` / `upper`（**弧度**） | `min_angle` / `max_angle`（**度**） |
| 零位 | 已写进电机（0x7019 读 0），`offset`=0 | `calibration.json` 的 `zero_offset_rad`（同为 0） |
| 正方向 | `direction` | `calibration.json` 的 `direction` |
| 限流 | `limit_cur` 参数（默认 6 A） | `adapter_config.limit_current_a` |
| 速度上限 | `max_speed`（rad/s） | `adapter_config.max_speed_rad_s` |
| CAN 接口 | `can_interface`（can0） | `adapter_config.can_interface` / 连接页端点 |
| 模型 | `arm_ws/src/arm_urdf/urdf/arm_urdf.urdf` | `model/arm.urdf` |

**唯一的数据源还是 `arm_ws/src/arm_urdf/config/joint_limits.yaml`。** 改完跑
`python3 arm_ws/src/arm_urdf/tools/sync_limits.py`，再跑本目录的
`python3 sync_from_ros.py` 就能把 `manifest.json` / `calibration.json` 一起刷新，不会出现两边不一致。

## 三、驱动实现了什么

契约里的方法全部实现（见 `driver_adapter/driver.py`）：

| 方法 | 行为 |
|---|---|
| `connect(port, baudrate, protocol)` | 打开 SocketCAN（`port`=接口名），写一次限流，起后台轮询线程 |
| `enable_all(True/False)` | 顺次：读当前位置 → 切 CSP → 写限速 → **先钉在当前位置** → 使能（不会一使能就跳） |
| `set_motor_angle(id, 度, speed)` | 夹到限位 → 换算弧度 → 写 0x7016 |
| `set_angles / set_all_joint_angles` | 批量同上 |
| `home_all_motors()` | 全部回 `default_angle`（现在是 0） |
| `get_latest_telemetry()` | 返回 `position`（度）/ `current` / `bus_voltage` / `online` / `error_code` 等，后台线程轮询，不阻塞 UI |
| `get_status(id)` | 单台 |
| `set_zero_point(id)` | 发通信类型 6，把当前姿态写成电机内部零位（断电不丢） |
| `set_max_current(id, q15)` | q15 → 0~11 A，写 0x2019 |
| `cleanup()` | 失能 + 关 socket |

未实现（可选）：`find_motor_limits` / `auto_find_limits` —— 自动寻限需要实机配合，暂时用 ROS 侧的
`calibrate.py jog/record` 手工量完再写进配置。

## 四、还没对上的地方（迁移时要处理）

1. **模型格式**：上位机用 MuJoCo 的 MJCF（`model/*.xml`），我们这边是 URDF。
   `model/arm.urdf` 先放进来保证信息不丢；要在上位机里看 3D，需要用 MuJoCo 的转换（把 URDF 转成 MJCF），
   需要的话我可以按 URDF 生成一份 MJCF 骨架。
2. **关节数**：URDF 里是 6 个关节（joint6 没有电机），包里的 manifest 只声明了 5 个有电机的关节；
   如果上位机要显示 6 关节模型，第 6 个要按"固定/被动"处理。
3. **反馈里的温度**：EL05 的反馈帧里带温度，但那是状态帧（0x02）；当前适配器读的是 0x701C 母线电压，
   温度字段先留 0。需要的话可以从状态帧解析补上。

## 五、和 ROS 侧是同一套协议

驱动里用的帧格式、参数索引、故障位定义，和 `el05_ws/src/robstride_ros_sample` 完全一致：

```
扩展帧 ID = (通信类型<<24) | (data16<<8) | motor_id     主机 0xFD
  0x03 使能   0x04 停止   0x06 置零   0x11 读参数   0x12 写参数
  0x7005 运行模式(5=CSP)  0x7016 位置  0x7017 限速  0x2019 限流
  0x7019 机械角  0x701A 电流  0x701C 母线  0x3022 故障码
故障位：bit2 欠压（<12V，锁存，需断电清） bit3 过压 bit14 堵转 bit16 A相过流 …
```

所以两边可以互换：ROS 跑仿真/算法，上位机做手调试，谁先谁都行。
