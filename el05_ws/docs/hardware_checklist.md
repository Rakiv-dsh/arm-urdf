# 硬件清单与接线（依据两份手册 + 两个仓库）

来源：`manuals/EL05使用说明书2600428.pdf`、`manuals/USB_CANHUB使用说明V1.0.pdf`、`docs/MOTOR_MAPPING.md`、`docs/PROJECT_LOG.md`

## 一、必须有的（缺一样就不通）

| 物件 | 规格（手册原文） | 现在状态 |
|---|---|---|
| 电机 | RobStride EL05 ×5，Φ41 mm，242 g，减速比 9:1，14 bit 单圈绝对值，CAN 1 Mbps | 你手上 |
| 电源 | **48 VDC 额定，允许 15~60 V**；单机额定相电流 2.6 Apk / 最大 11 Apk | 待确认（48 V 电源 + 量过电压吗） |
| CAN 适配器 | 灵足 USB_CANHUB，5 路，Type-C 5 V 供电（不额外供电），Linux 下生成 can0~can4 | ✅ 已接进 WSL |
| 电机电源+信号线 | 电机端 **XT30(2+2) 四芯**（AMASS XT30(2+2)-F.G.B）：2 芯 48V/GND + 2 芯 CANH/CANL | 待确认 |
| CAN 转接线 | CANHUB 端是 **2.54 mm 3P 对插端子：H / L / GND** | 待确认 |
| 终端电阻 | CANHUB 每路有**拨码开关，ON = 接入 120 Ω**；总线两端各 120 Ω | ⚠️ 最可疑 |

## 二、手册里三条直接对得上的判据

1. **拨码开关**（CANHUB 手册第 9 页）："拨码开关：Can120 欧姆电阻配置开关，ON 状态为接入电阻 120 欧姆。"
   EL05 手册进一步明确："当拨码开关 2 置于 ON 位置时，模块端口会接入 120Ω 终端电阻，**从而支持与上位机正常通信**。"
   → 拨码 1 是 Boot 模式，**必须 OFF**（否则 USB 都认不到，我们这里认到了，说明 1 是对的）；拨码 2 是 120 Ω，**要 ON**。
2. **每路两个 LED**（手册第 9 页）：绿色 = 接收数据，红色 = 发送数据，LED2/4/7/8/11 是 5 路的绿，LED3/5/6/9/10 是 5 路的红。
   → 不用万用表：我发帧时**对应那路红灯该闪**；电机应答时**绿灯该闪**。
3. **XT30(2+2) 是四芯插头**：电源两芯 + CAN 两芯在同一个插头里，**没插到底就只有电没有 CAN**（或反之）。这是 EL05 最常见的"上电但不通信"原因。

## 三、软件侧（不需要额外硬件）

- 默认协议：**私有协议（29 位扩展帧）**；可切 CANopen / MIT（MIT 是 11 位标准帧，且要发通信类型 25 帧并重新上电）。
- 主机 ID：**253 = 0xFD**。
- 电机 CAN ID：8 位，出厂常见 127，要改成 1~5。改法有两种：
  - Windows 上 **Cangaroo**（仓库里带了 `cangaroo-workspace.xml`，能直接认 candleLight）；
  - 或者我这边用通信类型 7（Set_CAN_ID）帧直接改，不用装 Windows 工具。
- 设备 UID（如 `6302000c03b441a`）不是 CAN 地址，不能拿来当 motor_id。

## 四、拓扑：两种都行，别混

- 上游 `MOTOR_MAPPING.md` 用的是**一路一电机**（can0→ID1 … can4→ID5）；
- 上游 `PROJECT_LOG.md` 后来改成**一路挂多电机**（同一个 can0 + 分电器 + 不同 ID）。
- **不要把一个电机的 H/L 分到两路**，也不要两路并到同一条总线（两个 120 Ω 收发器硬顶，会报 bus-off）。
