## 两件要注意的

**1. MechOffset 不需要在 ROS 侧再扣一次。**
`MechOffset` 是电机内部用来定义「机械零位」的偏置，`0x7019` 读出来的 `mechPos` **已经是扣过它之后的机械角**。
所以 `five_dof_controller.yaml` 里的 `mech_offset` 默认全 0；如果整臂装好后某轴读数有恒定偏差，再按实测补进 yaml。
（上游仓库里那份 `[0, 0.265762, 0, 4.244908, 0]` 疑似把 MechOffset 抄进了 ROS 侧，会重复扣减，已改掉。）

**2. `CAN TIMEOUT = 0` 建议改成非 0。**
手册：值为 0 时不启用；非 0 时，电机超过设定时间收不到 CAN 指令就自动 reset（保护）。
按手册换算 20000 ≈ 1 s，所以 100 Hz 控制下填 `2000`（约 100 ms）比较稳妥——
上位机通信断了或被 Ctrl+C 掐掉时，电机会自己停，而不是保持最后一条指令一直顶着。

## 代码侧对应改动

- `five_dof_arm_controller` 新增参数 `motor_ids`（默认 `[21,22,23,24,25]`），`mech_offset` 默认全 0
- `el05_all_sine` 新增 `--base-id N`（默认 21，五台按 N..N+4）
- `el05_joint1_sine` / `el05_joint2_current_monitor` 新增 `--motor-id N`（默认 21 / 22）
- 以上已在虚拟总线（vcan + 虚拟电机 21~25）上验证：五台联合、单台都能正常握手与下发
